# Qodo Loop

Iteratively fix a PR until Qodo review is clean enough for human review: no active **Action required** findings, every **Review recommended** finding fixed or explicitly deferred with reasoning, and required CI checks passing.

## When to use

| Situation | Use `qodo-loop`? |
|-----------|------------------|
| Multiple Qodo Action required / Review recommended findings remain | Yes |
| Multiple rounds of Qodo feedback expected | Yes |
| You want an automated fix → push → re-review loop | Yes |
| First time checking a PR after opening it | No — use `check-pr` first |
| Only one minor Qodo comment | No — fix manually |

**Prerequisite:** Install and authenticate `gh` CLI (`gh auth login`). Qodo must be connected to the repo.

## Inputs

- **PR number** (optional): If not provided, detect the PR for the current branch.

## What each action means

| Action | What it does |
|--------|--------------|
| `/agentic_review` | Asks Qodo to review the **current remote HEAD** of the PR |
| Reply on a thread | Records whether a finding was fixed or deferred (and why) |
| Resolve thread | Closes the GitHub conversation for that finding |
| Commit | Records the local code fix in git history |
| Push | Updates the remote PR so the next Qodo review sees the fix |
| Re-review | Posts `/agentic_review` again after push so Qodo evaluates the new HEAD |

Qodo findings are **triaged**, not followed blindly. False positives and intentional behavior are deferred with a concrete reason.

## Instructions

### 1. Identify the PR

```bash
gh pr view --json number,headRefName -q '{number: .number, branch: .headRefName}'
```

Switch to the PR branch if not already on it.

### 2. Pre-flight checks

1. Working tree clean for **tracked** files (`git diff --name-only`, `git diff --cached --name-only`)
2. Push any unpushed commits — Qodo reviews remote HEAD only
3. Confirm no Qodo review is already in progress (see detection below)

### 3. Loop (max 5 iterations)

#### A. Trigger Qodo review

```bash
git push
```

Check whether a Qodo review is already running (in-progress comment markers, or a recent `/agentic_review` without a completed result). If not running, request a fresh review:

```bash
gh pr comment <PR_NUMBER> --body "/agentic_review"
```

Do **not** use legacy `/review`, `/improve`, or `@greptile review`.

#### B. Wait for Qodo review

Poll every **30 seconds**, max **10 minutes** per cycle.

**Bot authors:** `qodo-merge[bot]`, `qodo-ai[bot]`, `pr-agent-pro`, `pr-agent-pro-staging`

**In progress:** comments contain "Come back again in a few minutes" or "An AI review agent is analysing this pull request"

**Complete:** Qodo summary/inline comments exist without in-progress markers, or summary shows a zero-action banner ("Great, no actions required" or equivalent)

Do **not** use `gh pr checks` as the primary Qodo detector.

#### C. Fetch and deduplicate findings

```bash
gh api repos/{owner}/{repo}/pulls/<PR_NUMBER>/comments
gh api --paginate "repos/{owner}/{repo}/issues/<PR_NUMBER>/comments?per_page=100"
```

Deduplicate summary + inline by **issue title**:

- Prefer **inline** for file location
- Prefer **summary** for severity bucket and agent prompt
- Preserve exact titles and Qodo's bucket order
- Ignore struck-through / Resolved findings

**Buckets (read from Qodo markup, do not invent):**

| Bucket | Default loop action |
|--------|---------------------|
| Action required | Fix |
| Review recommended | Fix |
| Optional / advisory / informational | Defer (reply with reason) |

#### D. Oscillation guard

Before fixing, load prior round summaries whose body contains `Generated by qodo-loop skill` (heading `## Qodo Fix Summary — Round N`).

Build a decision ledger keyed by `file` + issue `title`:

| Tag | Meaning | Loop behavior |
|-----|---------|---------------|
| 🔁 Repeat | Same finding resurfaced after a prior fix | Re-read code; defer if prior fix intact |
| ⚠️ Contradiction | New suggestion reverses a prior fix or deferred decision | Do not auto-apply; defer with prior rationale unless user overrides |
| 🛑 Hard stop | Same key flipped direction ≥2 times | Refuse further changes at that location |

#### E. Exit conditions

**Success — stop the loop when all are true:**

1. Latest Qodo summary has **no Action required** findings
2. Every **Review recommended** finding is fixed or explicitly deferred with a reply
3. Required CI checks in `statusCheckRollup` are all passing
4. No unresolved actionable human review threads remain

**Partial exit — stop early when:**

- Max **5** iterations reached
- Oscillation hard stop at any location
- Qodo review timed out twice consecutively
- CI still failing after iteration 3 (investigate CI separately)

#### F. Fix actionable findings

For each untagged Action required / Review recommended finding (Qodo order, most severe first):

1. Read file context
2. Apply Qodo's **agent prompt** literally when present
3. If false positive or intentional — defer with a concrete reason on the thread
4. Skip oscillation-tagged issues per the guard above

#### G. Verify, commit, push

```bash
npm run check
git add <fix-related files only>
git commit -m "fix: address Qodo review feedback (qodo-loop iteration N)"
git push
```

Do not use `--no-verify` or force push. Commit only fix-related tracked files.

#### H. Reply, resolve, summarize

Reply on each addressed inline thread:

- Fixed: `✅ **Fixed** — <short description>`
- Deferred: `⏭️ **Deferred** — <reason>`

Resolve addressed threads via GraphQL:

```bash
gh api graphql -f query='
mutation {
  resolveReviewThread(input: {threadId: "THREAD_ID"}) {
    thread { isResolved }
  }
}'
```

Post a round summary comment:

```markdown
## Qodo Fix Summary — Round N

- Fixed: ...
- Deferred: ...
- Skipped to prevent oscillation: ...

Generated by qodo-loop skill
```

#### I. Next iteration

Go back to step A (trigger `/agentic_review` again after the push). Skip the trigger if a review is already running.

### 4. Report

```
Qodo-loop complete.
  Iterations:                    N
  Action required remaining:     N
  Review recommended remaining:  N (or N deferred)
  CI:                            passing | failing
  Oscillation stops:             N
```

## Safety limits

| Limit | Value |
|-------|-------|
| Max loop iterations | 5 |
| Max wait per review | 10 minutes |
| Poll interval | 30 seconds |
| Commits | One per iteration |
| Files committed | Fix-related tracked files only |
| Git safety | No `--no-verify`, no force push |
| Re-trigger | Skip if review already in progress |
| Auto-fix scope | Exclude oscillation-tagged issues unless user override |
| Local verify | `npm run check` before each loop commit |
